Веб-сервис, панель управления и фоновый планировщик на Python (FastAPI) для периодического мониторинга удаленных Git-репозиториев (GitHub / GitLab / Gitea) и автоматического запуска сборок в Drone CI через официальный REST API при появлении новых коммитов.

## 🌍 Почему создан этот проект: Проблема вебхуков GitHub в России

Классический подход CI/CD опирается на **Push-модель**:
```text
Разработчик делает push в GitHub ──(Webhook HTTP POST)──► CI-сервер Drone CI запускает сборку
```

Однако в **России и изолированных корпоративных контурах эта схема практически не работает**:

1. **Недоступность и блокировка входящих вебхуков от GitHub:**
   - Пул IP-адресов, с которых GitHub отправляет вебхуки (GitHub Webhook CIDR blocks), на территории РФ часто блокируется или испытывает проблемы со связностью из-за сетевых фильтраций и трансграничных ограничений.
   - В результате вебхуки от GitHub завершаются таймаутами (`connection timeout`, `SSL handshake failure`), и сборки в Drone CI просто не стартуют.
2. **Закрытый периметр, NAT и отсутствие публичного белого IP:**
   - Серверы Drone CI часто развернуты на локальных серверах компании, в закрытых ЦОД или за корпоративным NAT/файрволом. GitHub физически не может отправить запрос во внутреннюю локальную сеть без организации сложных VPN-туннелей.
3. **Ограничения хостингов и гео-блокировки:**
   - Попытки использовать сторонние прокси для проброса вебхуков часто упираются в нестабильность или блокировку промежуточных адресов.

### 💡 Решение: Внешний посредник и инициатор вебхуков (Pull-модель)

**Drone CI Build Sync** решает эту проблему фундаментально, выступая в роли **активного внешнего посредника и инициатора вебхуков**:

```text
[ GitHub / GitLab / Gitea ]
        ▲
        │  1. Исходящий опрос: `git ls-remote --heads` (за доли секунды, без скачивания кода)
        │
[ Drone CI Build Sync (Этот сервис) ]
        │
        │  2. Обнаружен новый SHA коммита в отслеживаемой ветке!
        ▼  3. Локальный вызов Drone API: POST /api/repos/{owner}/{name}/builds?branch={branch}
[ Сервер Drone CI ] ────► Пайплайн запускается (событие `trigger.event: custom`)
```

- **Исходящие HTTPS-соединения из РФ в GitHub работают стабильно.** Сервис сам инициирует исходящие запросы к Git-репозиторию, что не блокируется сетевыми фильтрами.
- **Никаких открытых входящих портов наружу.** Серверу не требуется публичный белый IP-адрес для получения вебхуков из интернета.
- **Минимальный трафик и нагрузка.** Опрос выполняется через `git ls-remote` (запрашиваются только заголовки веток и SHA, код не скачивается).

## ⚡ Основные возможности

- **⏰ Расписание работы воркера по дням недели (`/schedule`):**
  - Возможность ограничить время поиска новых коммитов по каждому дню недели (со скольки до скольки разрешено работать воркеру).
  - **Выбор часового пояса (Timezone):** поддержка таймзон (`zoneinfo`) с пересчетом локального времени (по умолчанию `Europe/Moscow`).
  - **Гибкие интервалы времени:** поддержка дневных окон (`09:00–18:00`), ночных окон с переходом через полночь (`22:00–06:00`) и круглосуточного режима (`00:00–00:00`).
  - **Глобально с переопределением в репозиториях:**
    - `Глобальное расписание`: единый график по умолчанию в разделе `/schedule`.
    - `Всегда 24/7`: опрос круглосуточно, игнорируя глобальные паузы.
    - `Индивидуальное расписание`: собственные часы и дни недели для конкретного репозитория.
  - **Экономия ресурсов:** вне разрешенных часов запросы в Git не отправляются.
  - **Ручной обход:** кнопка «Проверить сейчас» работает в любой момент, независимо от расписания.

- **🔑 Централизованный реестр креденшелов (`/credentials`):**
  - Единое место для хранения учетных записей Git (логины, Personal Access Token) и токенов Drone CI.
  - Привязка одного креденшела к нескольким репозиториям. Обновление токена в одном месте автоматически обновляет доступ во всех связанных проектах.
  - **Шифрование данных (Encryption At-Rest):** все пароли и токены шифруются в БД алгоритмом Fernet (AES-128-CBC + HMAC).

- **🔔 Модуль мгновенных нотификаций (`/notifications`):**
  - Оповещения о запуске сборок Drone CI и ошибках опроса.
  - **Telegram:** отправка в личный чат, канал или группу через Bot API.
  - **ВКонтакте:** отправка в личные сообщения или беседу группы через VK `messages.send` API.
  - **Email (SMTP):** поддержка TLS/SSL, аутентификации и списка получателей.
  - **Кнопки проверки:** возможность отправить тестовое уведомление прямо из веб-интерфейса.

- **📡 Живой журнал событий (Live SSE):**
  - Таблица логов в реальном времени по протоколу Server-Sent Events (SSE) без перезагрузки страниц.
  - Фильтрация по репозиториям и уровням важности (info, success, warning, error).
  - Кнопки быстрой очистки истории журнала.

- **📊 Метрики Prometheus (`/metrics`):**
  - Экспорт счётчиков сборок, гистограмм длительности опроса, ошибок и состояния отслеживаемых веток для дашбордов Grafana.

- **🌐 Отслеживание веток:**
  - Поддержка отслеживания **всех веток** либо перечня конкретных веток и масок (например: `main, develop, staging, release/*`).
  - Автоматическое определение веток, удаленных в remote-репозитории.

- **🛡️ Защита от гонок и дублей:**
  - Мьютексы `asyncio.Lock` предотвращают параллельный опрос одного и того же репозитория и дублирующие запуски сборок.
  - Маскирование секретов в URL (`***:***`) исключает утечку учетных данных в логи и веб-интерфейс.

- **📦 Полная автономность (Air-Gapped / Intranet):**
  - Стили Tailwind CSS вендорятся локально в `app/static/css/`, сервис полноценно работает в закрытых сетях без доступа к публичным CDN.

## 🚀 Быстрый старт

### Вариант 1. Запуск через Docker Compose (Рекомендуется)

```bash
# 1. Клонирование репозитория
git clone https://github.com/shpion34rus/drone-ci-build-sync.git
cd drone-ci-build-sync

# 2. Запуск в фоновом режиме
docker compose up -d --build
```

Интерфейс будет доступен по адресу:
- **Панель управления:** [http://localhost:8080](http://localhost:8080)
- **Документация REST API:** [http://localhost:8080/api/docs](http://localhost:8080/api/docs)
- **Метрики Prometheus:** [http://localhost:8080/metrics](http://localhost:8080/metrics)

---

### Вариант 2. Локальный запуск (Python Virtualenv)

**Требования:** Python 3.10+ и утилита `git` в системе.

```bash
# 1. Создание и активация виртуального окружения
python3 -m venv .venv
source .venv/bin/activate  # Для Windows: .venv\Scripts\activate

# 2. Установка зависимостей
pip install --upgrade pip
pip install -r requirements.txt

# 3. Запуск сервиса
python3 main.py
```

## ⚙️ Обязательная настройка `.drone.yml` (Событие `custom`)

Так как сборки инициируются сервисом извне через официальный REST API Drone CI, Drone присваивает таким сборкам тип события **`custom`**.

В файле `.drone.yml` целевого репозитория обязательно укажите событие `custom` в блоке `trigger`:

```yaml
kind: pipeline
type: docker
name: default

steps:
  - name: test
    image: python:3.11-slim
    commands:
      - pip install -r requirements.txt
      - pytest

  - name: build
    image: docker:dind
    commands:
      - docker build -t myapp .

trigger:
  event:
    - push
    - custom   # <--- ОБЯЗАТЕЛЬНО для работы Drone CI Build Sync!
```

## ⏰ Настройка расписания работы воркера

Для того чтобы воркер искал коммиты только в рабочее время (например, по будням с 09:00 до 18:00):

1. Перейдите во вкладку **«Расписание»** в верхнем меню.
2. Включите тумблер **«Включить опрос строго по расписанию»**.
3. Выберите нужный часовой пояс (например, `Europe/Moscow (UTC+3)`).
4. Задайте разрешенные часы по каждому дню недели или воспользуйтесь быстрыми шаблонами:
   - ⚡ **Будни 09:00–18:00**
   - ⚡ **Будни 10:00–19:00**
   - ⚡ **Все дни (00:00–23:59)**
5. При необходимости в настройках конкретного репозитория можно переопределить график:
   - `Как в общем расписании`: следовать глобальному графику.
   - `Всегда круглосуточно (24/7)`: опрашивать независимо от глобальных пауз.
   - `Индивидуальное расписание`: собственные дни недели и часы для данного проекта.
