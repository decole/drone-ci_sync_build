1. Принцип работы сервиса (Pull-модель и внешний посредник)

⚠️
Почему вебхуки GitHub не доходят: В России входящие вебхуки от GitHub часто блокируются или недоступны из-за сетевых ограничений, блокировок диапазонов IP-адресов и закрытых корпоративных контуров (NAT/файрволы). В результате стандартная отправка push-вебхуков от GitHub к локальному или арендованному серверу с Drone CI не работает.

Drone CI Build Sync выступает в роли внешнего посредника и инициатора вебхуков с pull-моделью: вместо пассивного ожидания входящих запросов от GitHub сервис самостоятельно опрашивает удаленные репозитории и инициирует сборку:

1. Быстрый опрос

Периодически запускает команду git ls-remote без тяжелого клонирования репозитория.

2. Фиксация коммитов

Сравнивает текущий SHA ветки с ранее сохраненным в базе данных SQLite.

3. Вызов Drone API

При обнаружении нового SHA инициирует сборку через официальный Drone REST API.

⚙️

2. Настройка .drone.yml: событие «custom»

⚠️ Почему это необходимо и для автоматического, и для ручного запуска:

Поскольку сервис обращается к Drone CI через REST API (POST /api/repos/{owner}/{repo}/builds?branch=...), Drone CI по спецификации всегда маркирует такие сборки типом события «custom».

Это происходит в обоих случаях:

  • когда фоновый воркер обнаруживает новый коммит и инициирует запуск сборки;
  • когда вы нажимаете кнопку «🚀 Запустить билд» в карточке репозитория.

Если в файле .drone.yml секция trigger ограничена только push и pull_request, Drone CI отклонит запуск пайплайна со статусом в логах:

{"event":"custom","level":"info","msg":"trigger: skipping pipeline, does not match event"}

Пример корректной настройки .drone.yml:

# .drone.yml
kind: pipeline
type: docker
name: ci-cd

trigger:
  event:
    - push
    - pull_request
    - custom # ОБЯЗАТЕЛЬНО: для опроса через API и ручных запусков

Как защитить шаги деплоя (Production):

Если вы не хотите, чтобы ответственные шаги (например, боевой деплой на production-сервер) запускались при ручном запуске или не-push событиях, ограничьте их индивидуально через when.event внутри самого шага:

  - name: production-deploy
    image: appleboy/drone-ssh
    when:
      event:
        - push # этот шаг сработает только при стандартном push
      branch:
        - main

3. Пошаговая настройка репозитория

1
Получите персональный токен Drone CI

В веб-интерфейсе вашего Drone CI нажмите на аватар в правом верхнем углу → User Profile → скопируйте значение из поля Your Personal Token.

2
Сохраните креденшелы в разделе «Креденшелы»

Добавьте учетные данные в реестр (/credentials). Токены шифруются алгоритмом Fernet (AES-128-CBC) и могут быть привязаны сразу к нескольким репозиториям.

3
Добавьте репозиторий

Перейдите в «Добавить репозиторий». Заполните URL Git-репозитория и имя в Drone CI (в формате owner/repo). Нажмите «🧪 Проверить подключение», чтобы убедиться в доступности веток и API до сохранения.

4
Настройте интервал опроса и ветки

Выберите опцию «Отслеживать все ветки» либо перечислите конкретные ветки через запятую. Задайте интервал опроса (по умолчанию 2 минуты).

🔔

4. Мониторинг, живой журнал и нотификации

Живой журнал событий (SSE)

На странице /logs и в деталях репозиториев таблица обновляется моментально по протоколу Server-Sent Events без перезагрузки вкладки.

💬 Telegram, ВКонтакте и Email

В разделе /notifications вы можете настроить мгновенную отправку отчётов о запущенных сборках и ошибках опроса.

⏰

5. Расписание работы воркера по дням недели

Сервис позволяет задавать временные интервалы (со скольки до скольки) для каждого дня недели, чтобы фоновый воркер искал новые коммиты только в рабочее время и не нагружал внешние Git-серверы и Drone CI во внерабочие часы или выходные дни:

Глобальное расписание

В разделе Расписание можно задать единый график по умолчанию для всей системы с выбором часового пояса и готовыми шаблонами (например, будни 09:00–18:00).

Индивидуальное переопределение

В параметрах каждого репозитория можно выбрать: следовать общему графику, опрашивать всегда круглосуточно (24/7) или настроить персональные часы и дни недели. При этом кнопка «Проверить сейчас» работает всегда.
